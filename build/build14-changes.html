XDRMonitorControl — build 14

What changed, and the one thing left for you to do.

1. The popout menu layout

Every element now derives from a single set of measurements, so the sliders, the display card and the settings row all sit on one column. Four separate defects are gone.

Drawn to scale from the measured geometry, 1 px = 1 pt. The dashed outline is one menu item; the rounded box is the display card.

Verified by build/layoutcheck.swift: 11 assertions, all passing, for both the on and off states of the percentage readout.

2. The XDR brightness colour

Pushing the brightness slider past normal maximum now runs the filled track through yellow → orange → red instead of a single flat red. A thin marker line sits at the point where standard brightness ends, so you can see where the HDR zone starts before you get there.

The colour is tied to the brightness value, not to how far the slider happens to be dragged, so the same brightness always looks the same.

3. Docked and undocked

Checked rather than changed — this part was already sound. The app asks macOS for the list of online displays each time the display setup changes, so closing the lid removes the built-in panel and opening it brings it back, with its XDR setting restored from what was saved. A stale "not XDR" verdict left over from the original faulty probe is discarded automatically.

Worth knowing: while the lid is shut, the built-in panel is offline, so there is nothing for the XDR code to act on. That is why the launch flash you originally reported cannot be reproduced in clamshell — it needs the lid open.

4. The hardware volume keys — one step for you

Found it, and it was not the volume code at all. The app has to ask macOS for permission to intercept the brightness and volume keys, and macOS is refusing. So the keypresses never reach the app, and because your LG does not accept volume changes through the normal macOS route, nothing happens at all.

Your sliders work because that path is completely separate — plain DDC over the display cable, no permission involved.

The reason it broke: that permission is tied to the app's exact build signature, and every rebuild changes it. System Settings carries on showing the app as switched on, so it looks like it should be working. The app now detects this properly and told you about it in the dialog that appeared a moment ago.

To fix it: System Settings → Privacy & Security → Device Control and Data Access (this row was called “Accessibility” before macOS 27 — see build21-permissions.html). Select XDRMonitorControl, remove it with the − button, then add it back with + and pick it from Applications. Ticking the existing checkbox is not enough — the recorded signature has to be replaced. Build 21 makes this a one-time job by signing with a stable certificate instead of ad-hoc.

Also changed: the volume keys now follow whatever your Mac is currently playing sound through, which is how macOS's own volume keys behave. So when the LG is the output device they drive the LG, and when you are undocked they go back to the Mac's own speakers. You can change this under Settings → Keyboard.
